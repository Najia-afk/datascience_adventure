Building an Autonomous AI: Aria's 5-Layer Architecture

How a native Python engine, multi-model routing, and persistent memory combine to create an AI that manages itself like a CEO

Author: Najia  |  Project: Aria Blue

The Problem

Most AI "agents" are glorified chain-of-thought wrappers. They follow a script, call tools in sequence, and return results. They don't think about what they're doing. They don't manage priorities, track long-term goals, or improve their own workflows.

Aria Blue was built to be different — an autonomous agent that operates like a CEO with specialized departments, each handling a domain of expertise, all coordinated through a centralized orchestration engine.

The 5-Layer Architecture

Every component in Aria follows a strict layering principle. No layer may skip another — this prevents the spaghetti dependencies that kill most agent systems.

Layer 1: Database

PostgreSQL 16 with dual database isolation — one for Aria's data (goals, memories, skills, conversations), one for LiteLLM's routing and usage tracking. No cross-database queries. Clean boundaries.

Layer 2: ORM

SQLAlchemy 2.0 with full async support via psycopg 3. All models live in src/database/. No raw SQL anywhere else in the codebase.

Layer 3: API

FastAPI with Strawberry GraphQL. This is the only layer that talks to the ORM. Everything above goes through HTTP endpoints.

Layer 4: Skills

Skills are Aria's capabilities — browsing, file operations, git, memory management. Every skill communicates with the API via api_client (httpx). No skill may import SQLAlchemy or call another skill directly.

Layer 5: ARIA Mind & Agents

The orchestration layer. Aria's "mind" coordinates specialized focus personas (DevOps Agent, Research Agent, Writing Agent) through roundtable discussions, delegates tasks, and synthesizes results. This layer only talks to Skills.

The Multi-Model Router

Aria doesn't depend on a single LLM. Through LiteLLM, she routes requests to the best model for each task:

Orchestration Claude Opus/Sonnet via OpenRouter
Fast Tasks Claude Haiku / GPT-4o-mini
Long Context Moonshot/Kimi (128K context)
Local Inference MLX on Apple Silicon Metal GPU

The Autonomous Work Cycle

Every 6 hours, Aria runs a goals review: she assesses priorities, evaluates progress, identifies new opportunities, and schedules tasks. Between reviews, she runs exploration pulses — browsing, researching, learning — and stores findings in her persistent memory.

This isn't a cron job running a script. Aria decides what to research, evaluates what she finds, and files it with context about why it matters to her work.
