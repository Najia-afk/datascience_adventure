How Aria Maps & Navigates Her Own Skills

35 skills, 225 tools, and a graph that connects them all — how path-finding algorithms turn a flat capability list into an explainable reasoning engine.

Knowledge Graph

Skill Graph

Most AI systems treat their capabilities as a flat list: “I can do X, Y, Z.” Aria treats hers as a graph — a web of interconnected skills where the relationships between capabilities matter just as much as the capabilities themselves. The result? An AI that can reason about how to combine skills, not just which skills it has.

The Problem With Flat Capability Lists

When you ask a typical AI agent “Can you help me deploy a machine learning model?”, it searches its tool list for something tagged “deployment.” If it finds one, great. If not, it either fails or hallucinates a capability it doesn't have.

But deployment isn't a single skill — it's a chain. You need model serialization, Docker containerization, API framework knowledge, reverse proxy configuration, and monitoring setup. A flat tool list doesn't encode these relationships. A graph does.

Anatomy of the Skill Graph

Aria's knowledge graph has three types of nodes and multiple edge types:

🎯 Skill Nodes

35 total. High-level capabilities like “Data Processing,” “Model Training,” “API Development,” “Infrastructure.” Each skill has a proficiency score and usage frequency.

🔧 Tool Nodes

225 total. Concrete tools: “pandas_read_csv,” “docker_build,” “git_commit,” “psql_query.” Each tool belongs to one or more skill categories.

🔗 Edge Types

requires (skill A needs skill B), enables (completing A unlocks B), contains (skill has tools), synergizes (A + B is more than the sum).

Why Graph > List

Composability

The graph reveals skill chains that aren't obvious from a flat list. “Data Ingestion → Processing → Feature Engineering → Training” is a pipeline you can only discover by traversing edges.

Explainability

“I used SHAP because the path from Model Evaluation to Report Writing goes through Explainability.” The graph is the explanation.

Gap Detection

If there's no path between “Raw Data” and “Production API,” that gap is a concrete learning objective. The graph makes capability holes visible.

Novel Combinations

Path finding can discover tool combinations that were never explicitly programmed. The synergy edges enable creative problem-solving.

Under the Hood

The path-finding algorithm is a weighted BFS that factors in skill proficiency, tool reliability scores, and edge type weights:

def find_skill_path(graph, start_skill, target_skill): # Weighted BFS — prefer high-proficiency, high-reliability paths queue = [(start_skill, [start_skill], 0)] visited = set() while queue: queue.sort(key=lambda x: x[2]) # sort by cost current, path, cost = queue.pop(0) if current == target_skill: return path, cost visited.add(current) for neighbor, edge in graph.neighbors(current): if neighbor not in visited: edge_cost = compute_edge_cost( edge_type=edge.type, proficiency=neighbor.proficiency, reliability=neighbor.avg_success_rate ) queue.append((neighbor, path + [neighbor], cost + edge_cost)) return None # no path → capability gap detected

The Map Is the Territory

When your AI's capabilities are a graph, every task becomes a pathfinding problem, every explanation becomes a traversal log, and every failure becomes a discoverable gap. The graph isn't documentation — it's the reasoning engine itself.
